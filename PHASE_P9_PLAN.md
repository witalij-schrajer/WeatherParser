## 2. Goal, binding scope and exclusions

Goal: a release-ready, versioned `WeatherParser.Parsing` NuGet package as the primary product, with documented identity, versioning, reproducibility, public API baseline, contents, checksums and source conditions, independently consumable without a source checkout; the example CLI with a documented deployment model on Debian 13 ARM64; English operating guides for external scheduling, logging, request volume and broker set-up; and the ARM64 release acceptance of the release artifacts on the NanoPi R76S, with offline, live, broker and hardware evidence reported separately. Publication to a feed, a GitHub release and any deployment happen only with the user's explicit authorization (REQ-003, REQ-013).

In scope:
- the release contract (RL rows, section 3): package identity and versioning, feed and publication procedure, reproducibility, API compatibility baseline, branch and tag flow, release artifacts and checksums, the CLI deployment model, SDK and package updates, the coverage-gate question of CL-19 C, the operating guides, the open P3 verification items and the release documentation (REQ-004, REQ-005, REQ-013, REQ-017, REQ-091)
- package metadata and build settings for a release build (repository URL, project URL, description, tags, release notes link, symbols and source link as decided), package validation and a public API baseline (REQ-012, REQ-013, REQ-016)
- reproducible package builds or a documented, named limitation; checksums of every release artifact; traceable build and test evidence per artifact (REQ-005, DEVELOPMENT_PLAN.md P9)
- a release workflow or documented manual procedure that builds, tests and packs the release candidate without publication rights for untrusted pull request code (DEVELOPMENT_PLAN.md P1 "untrusted PR code"); publication as a separate, explicitly authorized action
- the CLI deployment model on Debian 13 ARM64 as an example: installation layout, service user, file permissions of the configuration and the credential file (CL-06), invocation from cron and n8n without a persistent process (REQ-006 to REQ-008)
- operating guides in English: configuration, scheduling with cron and n8n, exit codes and partial failures, log handling, request volume per source, broker set-up with dedicated credentials, TLS and scoped topic permissions, estimated dates, freshness, source conditions and limitations (REQ-007, REQ-061, REQ-062, REQ-090, REQ-092)
- the open broker checks of P3 (TLS and authentication against an authorized test broker) and the Windows shutdown item (RL-13, RL-14)
- the ARM64 release acceptance on the NanoPi R76S with the release artifacts: noninteractive single-command runs, real serializers, UTF-8, UTC and source time zones, file permissions, exit codes, channels, signals, cleanup, repeated scheduled invocations (REQ-004, REQ-005, REQ-017, REQ-084)
- the compatibility matrix `docs/COMPATIBILITY.md` updated with the release evidence (REQ-017)
- integrated verification, acceptance, the release on `master` and, only with authorization, publication

Out of scope with owner:
- library behavior, contract or public API changes: P9 changes no library behavior; a defect found is reported to the user and fixed only on a recorded decision (test-first through qwen, a new package build and a rerun of the affected verification) → user
- additive export contract changes (P2 v1 frozen) → not planned
- new commands, an internal scheduler, a persistent process, orchestrator installation (REQ-002, REQ-006 to REQ-008) → not planned
- MQTT error collection, history, additional providers, room stations (REQ-002, REQ-072) → future extensions
- publication of OsthessenWetter values (OW-14) → not before the user records the operator's consent or other clarified conditions
- additional ARM variants (ARM32), other operating systems as release targets (REQ-004) → possible later extension
- production operation of the user's home automation (broker, n8n, consumers) → outside WeatherParser (REQ-008)

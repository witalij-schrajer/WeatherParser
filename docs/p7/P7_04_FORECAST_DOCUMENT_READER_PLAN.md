# P7.04 – Secure KMZ/KML Forecast Reader: Implementation Plan

**Status: executed on 2026-10-27 (reconciled with the approved [P7 forecast contract](P7_FORECAST_CONTRACT.md) in P7.02 S6); Codex 5/1/0 ([verification record](P7_VERIFICATION.md) section 4).** Refines the P7.04 row of section 5 and the "Archive and XML" and "Structure" rows of section 4 of [PHASE_P7_PLAN.md](../../PHASE_P7_PLAN.md).

## 1. Goal and Scope
Goal: an injectable reader that turns a MOSMIX KMZ stream into one validated raw forecast document of the requested location — issue time, timeline, location and the raw token series per element — for the single-location MOSMIX_L file and for the streamed MOSMIX_S all-stations file, built on the secure archive and XML handling of the P4 evidence readers through shared internal components (SC-21), without interpreting units or periods.
In scope: shared internal archive and XML components extracted from `MosmixLEvidenceReader` and `MosmixSEvidenceRefresher` with their P4 tests unchanged as regression guard; the CRC-32 verification decided in P7.02 (MF-06), enforced only on the forecast paths; the structural rules of MF-07 including the retained-size bounds; placemark selection for both forms; failures with the MF-07/MF-14 IDs; synthetic KMZ fixtures through the existing `MosmixKmzBuilder` test helper (extended); registration.
Out of scope with owner: element-to-quantity mapping and periods → P7.05; retrieval, bounds of the HTTP body and deadlines → P7.06; logging → P7.07, P7.08.

## 2. Preconditions and Inputs
- P7.02 approved MF-03, MF-06, MF-07, MF-08, MF-12 and MF-14 on 2026-10-26 and recorded the schema derivation, the file facts and the CRC-32 result (the pinned runtime does not verify the entry CRC-32, contract section 7.1).
- Existing: `MosmixLEvidenceReader` (bounded in-memory archive, one `.kml` member, `XmlReader` with `DtdProcessing.Prohibit` and no resolver, the SC-20 token grammar), `MosmixSEvidenceRefresher` (streamed member, `BoundedNameTable`, counting stream, SC-22 bounds), `CatalogFormatException`, `MosmixKmzBuilder`.

## 8. Risks and Limitations
- (a) The compressed MOSMIX_S archive is held in memory up to 64 MiB because `ZipArchive` needs a seekable stream; recorded with the measured peak working set (P7.11)
- (b) The extraction touches P4 code; the unchanged P4 tests and the CRC characterization tests are the guard, and any behavior difference stops the step
- (c) Under option A the P4 selection evidence and the MOSMIX_S refresh do not detect a corrupted member that is still valid XML, unless the runtime verifies the CRC; recorded as a limitation with the user as owner (P7.12)

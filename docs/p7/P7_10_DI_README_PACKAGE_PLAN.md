# P7.10 – DI Registration, README and Package Consumption: Implementation Plan

**Status: executed on 2026-10-28 (reconciled with the approved [P7 forecast contract](P7_FORECAST_CONTRACT.md) in P7.02 S6; [verification record](P7_VERIFICATION.md) section 10).** Refines the P7.10 row of section 5 of [PHASE_P7_PLAN.md](../../PHASE_P7_PLAN.md).

## 1. Goal and Scope
Goal: prove that a consumer of the actual built package registers both MOSMIX parsers through `AddWeatherParsing` with its own endpoints and options, parses both products from synthetic files and serializes the runs, and document the MOSMIX forecast library for consumers.
In scope: integrated DI with consumer options for both products, independent containers and validation at build; the package-consumer tests from the same-run `.nupkg` (`tests/WeatherParser.Package.Tests`); README section "MOSMIX forecasts (library)" (source paths, element mapping table, update cycles of REQ-110 distinguished from publication availability and retrieval scheduling, freshness and `MaxRunAge`, the stale marker, the forecast-only members, retrieval guidance per product, the MOSMIX_S download cost, deadlines and the request bound, error and notice IDs, attribution and DWD terms of use, the schema compatibility note of C-105, the registration consequence for consumers that do not use MOSMIX forecasts); README feature status of MOSMIX parsing from planned to implemented; the README package check of CONTRIBUTING.md section 4.
Out of scope with owner: CLI → P3; MQTT topics → P8; publication → P9.

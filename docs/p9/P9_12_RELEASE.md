## 5. Equivalence of `b783881` with the P9 candidate `89a83d1`

The P9.10 target runs and the P9.11 runs were made on the library and CLI of `86e77eb` and `89a83d1` (version 0.1.0). The 1.0.0 artifacts were compared with the artifacts of `89a83d1` (release build 41507675695) by a script in the session scratchpad that reads both DLLs with `System.Reflection.Metadata`:

- Library `WeatherParser.Parsing.dll`: 2030 method bodies with identical IL, 4270 identical type, method, field and property names, identical assembly references, no manifest resources; the assembly version is 1.0.0.0 instead of 0.1.0.0.
- CLI `WeatherParser.dll`: 795 method bodies with identical IL and 1590 identical names; the only differing assembly reference is `WeatherParser.Parsing` 1.0.0.0 instead of 0.1.0.0.
- `compare-packages.ps1`: in the package `README.md`, the nuspec, the DLL and the package metadata member differ; in the CLI archive the two DLLs, `WeatherParser.deps.json` and the PDB.

So the behavior of the library and the CLI is that of the accepted P9 candidate; the differences are the version, the commit-derived identity data and the README. Whether the P9.10 target runs are repeated on 1.0.0 is the user's decision (section 1); until it is taken, the P9.10 evidence is that of the 0.1.0 build.

## 5. Procedure
No code change is planned; documentation by the orchestrating agent.

### S1 Broker preparation
The user prepares the test broker with TLS and the test CA, and two test identities scoped to test topic trees only: the integration-test identity with read and write permission on `weatherparser-test/#` (the opt-in broker tests publish and also subscribe with the same credentials under a per-run prefix `weatherparser-test/<guid>/`), and for the CLI checks a publisher identity with write permission only on the test topic tree of the test configuration plus an observer identity with read permission on that tree (the observer verifies topic, QoS and retain); no identity has permissions outside the test trees, and production publisher permissions stay separately scoped (RL-12 guide); the agent records the authorization.

### S2 Opt-in tests and CLI runs
From Windows and from the NanoPi: run the opt-in broker tests with TLS and credentials; then CLI runs in MQTT mode, on the NanoPi with the `linux-arm64` CLI acceptance artifact (P9.06, checksum verified), on Windows with a `win-x64` publish of the same candidate commit against the same-run package (built by the P9.06 procedure for this check only, its checksum and its resolved package hash recorded in the run record; not a release artifact): a successful `--ParseDWD` against the P9.07 fixture host (QoS 1, retained, observed by a subscriber), a wrong credential (rejected, its ID, exit 1), a wrong CA (TLS failure, its ID, exit 1), the broker's unencrypted port without `AllowUnencrypted` (no plaintext connection is made: the TLS attempt fails with its ID and exit 1); the credential file with mode `0600` owned by the running user.

### S3 Windows shutdown

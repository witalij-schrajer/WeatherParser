## 2. Goal, binding scope and exclusions

Goal: the example CLI `WeatherParser` as a consumer of the versioned package `WeatherParser.Parsing`: exactly one of the five commands per invocation, validated before any retrieval, deterministic configuration with secrets outside Git and process lists, output as MQTT (default), JSON or XML to stdout or to a file without partial or overwritten files, an example broker transport that reports success only after the QoS-1 acknowledgment, bounded timeouts and retries, controlled cancellation, logs on stderr only and documented exit codes, verified on Windows, hosted CI and the NanoPi R76S.

In scope:
- the CLI project consuming the package through a versioned `PackageReference` from the local feed, never through a `ProjectReference` or copied library code (REQ-012, REQ-013, C-112)
- command and option grammar: `WeatherParser --<command> [options]`, exactly one command, case-insensitive option names, duplicate, conflicting, unknown and missing options rejected before network access, help with commands, units and examples (REQ-010, REQ-011)
- the five commands `--SelectDWD`, `--ParseDWD`, `--ParseOstHessen`, `--SelectMOSMIX`, `--ParseMOSMIX --Product MOSMIX_S|MOSMIX_L` over the library services (REQ-002, REQ-020 to REQ-024 through the library, REQ-030, REQ-031, REQ-040, REQ-041, REQ-100 to REQ-103, REQ-111)
- configuration format, location, environment variables and precedence; the DWD reference station; source endpoints and options forwarded unchanged to the library registrations; topic configuration for `MqttTopicOptions`; secrets (REQ-014, REQ-016, REQ-030, REQ-060, REQ-064)
- `--Output mqtt|json|xml` (default `mqtt`) and `--OutputFile`: no broker in JSON/XML mode, one complete document, UTF-8, no silent overwrite, no misleading partial file (REQ-065 to REQ-069, REQ-073)
- the example MQTT transport: broker, port, TLS (never generally disabled), credentials, publication of the library's `MqttMessage` unchanged, success only after acknowledgment, bounded connection and publication timeouts, bounded retries, partial-failure summary (REQ-060, REQ-062, REQ-063)
- logging to stderr with UTC, severity, stable error ID, command and source or station, without secrets (REQ-072, REQ-073); exit codes for success, partial failure and complete failure (REQ-007, REQ-063, REQ-068); controlled cancellation (REQ-006, REQ-007)
- the OW-14 publication restriction in the CLI, the MOSMIX_S evidence-refresh exposure decision (SC-22)
- process tests of the built CLI (single execution and termination, channels, exit codes, files), an explicitly enabled broker integration test against a test broker, authorized live checks, README and CONTRIBUTING updates, integrated verification, acceptance and the P9 handoff

Out of scope with owner:
- library changes: P3 changes no library behavior, contract or public API; a defect found in the library is reported to the user and fixed only on a recorded decision (test-first through qwen, with a new package build and a P3.11 rerun) → user
- an internal scheduler, polling, a persistent process or orchestrator installation (REQ-006 to REQ-008) → not planned
- MQTT error collection (REQ-072 "future feature") → not planned
- publication of OsthessenWetter values (OW-14) → not before the user records the operator's consent or other clarified conditions
- package ID, feed, publication, release artifacts and checksums, deployment model, operating guides for cron and n8n beyond the README examples → P9
- additional providers, history, room stations (REQ-002) → future extensions

## 2. Goal, binding scope and exclusions

Goal: two separate library services, `IMosmixSParser` and `IMosmixLParser`, that each retrieve the latest run of their product for one consumer-supplied MOSMIX ID from consumer-supplied endpoints, read the KMZ/KML securely and return one P2 `forecast_run` with separate `issued_at`, `retrieved_at` and `valid_at`, proven offline with synthetic KMZ fixtures and the real serializers.

In scope:
- the two public parser contracts of REQ-104 and REQ-109, each with its own endpoints, options, DI registration and error IDs; shared internal KMZ/KML components allowed; no product switch, no fallback between products, no cross-product state (REQ-109, REQ-111)
- validation of the MOSMIX ID before any request (REQ-103, C-69), with the product-specific grammar fixed in P7.02
- bounded retrieval of the latest run per product (REQ-104, REQ-108): MOSMIX_L from the per-location file `MOSMIX_L_LATEST_<id>.kmz`, MOSMIX_S from the all-stations file (the only published MOSMIX_S form, P4 selection contract section 3.3)
- secure KMZ and XML reading built on the P4 readers (SC-20, SC-22, SC-21 reuse obligation): one `.kml` member, compressed and uncompressed bounds enforced while streaming, DTDs prohibited, no resolver, no external resources, nothing written to disk (REQ-108)
- full validation of namespaces, product definition, issue time, forecast timeline, the location placemark and the parameter series against the binding schema `pointforecast_dwd_extension_V1_0.xsd` revision V1_0 (REQ-104, REQ-107, REQ-112), with the schema revision and SHA-256 recorded
- the element-to-quantity mapping with verified units, pressure reference and periods from the DWD element definitions (REQ-106, REQ-055, REQ-052); missing markers omitted at their own time without shifting later values (REQ-107, C-77)
- forecast-only quantities (gusts, totals, probabilities) only as recorded additive export-contract decisions (C-03, C-73, C-105), or recorded as not exported
- run freshness per product: product-specific age limits and a marker for runs older than the limit (REQ-104 "do not present old runs as current without a marker", REQ-110)
- run assembly through `IForecastRunBuilder` (C-75 to C-78); no parallel builder
- export equivalence and schema validation of the produced runs (REQ-067 to REQ-069, REQ-077, REQ-079)
- the MOSMIX element verification left open by P4 (REQ-102, P4 selection contract section 5): the element vocabulary used by selection evidence and by forecast parsing checked against the same element definitions
- DI registration, README consumer guidance (source paths, update cycles, freshness, retrieval guidance, attribution) and package-consumer evidence (REQ-012 to REQ-016, REQ-090, REQ-110)
- integrated coverage and platform verification, including the resource behavior of the MOSMIX_S all-stations file on the NanoPi R76S; acceptance and P8 handoff

Out of scope with owner:
- the CLI options `--ParseMOSMIX`, `--Product`, `--MOSMIXID`, the rejection of a missing or unknown product before retrieval as a CLI behavior, output modes, files and exit codes (REQ-065, REQ-066, REQ-103 CLI part, REQ-111 CLI part) → P3; in P7 the product is selected by choosing the parser interface, and the DEVELOPMENT_PLAN.md P7 acceptance wording "`--ParseMOSMIX --Product … --MOSMIXID`" is demonstrated through the library API (as P5 and P6 did for their commands)
- MQTT messages, forecast topics, QoS and retained semantics of complete runs (REQ-061, REQ-062) → P8; P7 provides the product-specific `source` of C-68 that P8 builds on
- changes to MOSMIX location selection (REQ-100 to REQ-102 were delivered in P4); P7 only verifies the element vocabulary and records any finding as a P4-contract amendment proposal for the user
- an example-CLI command for the MOSMIX_S evidence refresh → user, P3 (SC-22, unchanged)
- a forecast cache, history or a scheduler; retrieval timing → external orchestration (REQ-006 to REQ-008)
- derived quantities without a documented formula, for example humidity from temperature and dew point, unless P7.02 records a formula and the user approves it (REQ-106)
- publication → P9

No change of export contract v1 except additive optional members with a recorded decision (C-03, C-105).
